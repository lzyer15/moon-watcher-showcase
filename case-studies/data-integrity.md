# 사례 3 · 주문 누적값과 알 수 없는 값을 구분하기

## 문제

주문 API를 반복 조회하면 같은 주문의 누적 체결값을 다시 받습니다. 이를 매번 새로운 체결로 더하면 거래량과 결과가 중복 집계될 수 있습니다. 조회 가능한 주문 자료를 계좌 전체 자산이나 확정 수익률로 확대 해석하는 문제도 피해야 했습니다.

## 원본 주문을 갱신하기

계좌와 주문 식별자를 기준으로 기존 기록을 갱신하고, 원본 주문과 파생 거래·기간 집계를 분리했습니다.

아래는 처리 원리를 설명하기 위한 **가상 예시**입니다. 실제 주문이나 거래 자료가 아닙니다.

| 같은 가상 주문의 조회 순서 | API 누적 체결 수량 | 저장할 주문의 누적 수량 |
|---|---:|---:|
| 첫 조회 | 2 | 2 |
| 다음 조회 | 3 | 3 |
| 동일 응답 재조회 | 3 | 3 |

마지막 누적 수량은 3입니다. 조회값을 2 + 3 + 3으로 합산하지 않습니다. 이 주문 스냅샷만으로 모든 개별 체결 시각과 가격을 복원할 수도 없습니다.

과거 자료는 구간별 수집 완료 지점을 관리하고, 완전한 수집 스냅샷과 최근 주문 보정 상태를 구분합니다. 완료 범위와 게시 시각을 따로 확인해 오래된 자료를 최신 결과처럼 표시하지 않도록 합니다.

## 지표의 의미를 제한하기

- 완료 거래의 추정 손익과 거래·기간 수익률을 집계합니다.
- 기간 수익률은 손익 합계를 해당 매입금액 합계로 나눕니다. 일별 비율의 단순 평균이 아닙니다.
- 주문 집계로 계산한 수익률을 계좌 전체 수익률로 부르지 않습니다.
- 조회 가능한 자산 참고값을 확정 현금 잔고·총자산과 구분합니다.
- 미수집·불완전 값은 빈칸과 상태로 남기며, 실제 0과 구분합니다.

## Sheets 쓰기 범위를 제한하기

게시 전 자동 관리 대상 표시와 헤더를 확인하고 지정된 자동 탭·범위만 갱신합니다. 사용자 수기 영역과 원본은 별도로 보존합니다. 수집 성공과 시트 게시 성공도 다른 상태로 관리합니다.

## 검증과 결과

누적값 갱신, 완료 거래 집계, 기간 합산과 수익률 정의를 관련 테스트로 검증했습니다. 실제 적용 단계에서는 시트 집계·수식과 원본 집계의 대조도 수행했습니다. 이 문서에는 그 과정의 계좌·주문 식별자, 거래 내역과 성과 수치를 옮기지 않았습니다.

계좌 원장 전체와 대조한 확정 수익률은 아직 제공하지 않습니다. 과거 현금 잔고와 입출금 자료처럼 확보하지 못한 값은 만들어 넣지 않았습니다.

## 배운 점

데이터가 도착했다는 사실과 그 데이터로 특정 지표를 계산할 수 있다는 사실은 다릅니다. 원본의 의미, 완료 범위, 집계 정의와 쓰기 소유권을 먼저 정해야 대시보드 숫자를 신뢰할 수 있습니다.
